# 完成记录与执行时间统一设计

## 背景

当前版本同时持久化 `completionFacts` 与 `executionRecords`。一次完成可能已经产生完成事实、奖励和结算结果，却没有生成独立执行记录。时间轨迹只投影 `executionRecords`，因此出现“本周已有完成记录，但时间线完全为空”的非法状态。

根因不是历史数据缺失，而是领域模型把同一次完成拆成了两套可独立变化的事实。

## 设计原则

一次完成只产生一条权威完成记录。完成记录本身就是执行事实，同时承载：

- 完成的行动；
- 完成时间和来源；
- 零个或多个实际执行时间段；
- 完成时冻结的奖励快照；
- 撤销状态。

实际执行时间允许为空。缺少实际时间不影响“已经完成”的真实性，也不能让完成记录从时间轨迹中消失。

## 数据模型

`CompletionFact` 增加 `actualSegments`：

```ts
type CompletionFact = Readonly<{
  id: string;
  planId: string;
  completedAt: string;
  source: "week-up" | "learning-more";
  externalFactId?: string;
  actualSegments: readonly PlanTimeSegmentInput[];
  rewardSnapshot: readonly AttributeReward[];
  revertedAt?: string;
}>;
```

顶层 `WeekUpState.executionRecords` 和独立的 `ExecutionRecord` 类型不再作为持久化模型存在。一次完成包含多个实际时间段时，仍然只有一条 `CompletionFact`；时间轨迹在投影阶段把这些时间段展开为多个可视条目。

## 写入与撤销

### 完成行动

`plan.complete` 原子地创建一条 `CompletionFact`：

- 用户确认了实际时间时，写入全部 `actualSegments`；
- 来源没有提供实际时间时，写入空数组；
- 奖励快照和 XP 继续与该完成记录关联。

重复导入同一外部完成事实时，只补充或更新同一完成记录的来源标识与实际时间段，不创建第二套执行事实。

### 分段完成

行动分段完成时，将已经确认的实际开始和结束时间写入对应行动分段的 `actualStartAt`、`actualEndAt` 字段。最后一个分段完成并生成 `CompletionFact` 时，将所有已确认的实际执行段汇总到该完成记录。完成记录创建后，行动分段仍保留这些字段作为编辑状态，但时间轨迹只读取完成记录。

### 撤销

撤销完成只需将对应 `CompletionFact` 标记为已撤销，并生成 XP 补偿。时间轨迹直接排除已撤销的完成记录，不再需要同步撤销另一张执行账本。

## 时间轨迹投影

时间轨迹直接读取有效 `CompletionFact`：

- `actualSegments` 非空：按每段真实的开始日期和起止时间绘制到时间轴；
- `actualSegments` 为空：按 `completedAt` 的上海本地日期放入当天顶部“未配置时间”区；
- 同一完成记录包含多个实际时间段时，时间轴可显示多个条目，但详情和编辑入口仍指向同一行动与完成事实。

“未配置时间”区域在日程与时间轨迹两种模式下都可见：

- 日程模式展示尚未安排时间的计划；
- 时间轨迹模式展示已经完成但没有实际执行时间的记录。

空状态只在当前视图范围内既没有已配置时间的完成记录，也没有未配置时间的完成记录时出现。

## 状态迁移

模式版本升级时执行确定性迁移：

1. 遍历所有现有 `completionFacts`。
2. 按 `completionFactId` 优先匹配现有有效 `executionRecords`；旧记录缺少关联字段时，仅当该 `planId` 只有一条有效完成事实时按 `planId` 匹配。
3. 将匹配到的执行记录按开始时间排序，并转换为该完成记录的 `actualSegments`。
4. 没有匹配执行记录的完成事实写入空数组。
5. 已撤销的执行记录不进入有效完成记录。
6. 完成迁移后移除顶层 `executionRecords`。

迁移不得使用计划的排期时间或 `completedAt` 伪造实际执行时段。旧完成记录没有实际时间时，应进入“未配置时间”区。

迁移必须幂等：已经包含 `actualSegments` 的新版本状态再次加载时，不重复追加时间段。

## 兼容性与错误处理

- Learning MORE 提供有效 `actualStartedAt` 与 `actualEndedAt` 时写入实际时间段；缺任一端或范围无效时保留空数组。
- 同一完成事实重复同步时，相同时间段去重。
- 行动被永久移除后，现有完成与回放策略保持不变；时间轨迹只显示仍可解析到行动内容的记录。
- 数据库升级继续沿用现有迁移前备份机制。

## 验证

回归测试覆盖：

1. 完成记录没有实际时间时仍出现在时间轨迹的“未配置时间”区。
2. 一条完成记录包含一个或多个实际时间段时，时间轴正确展开。
3. 时间轨迹不再依赖顶层 `executionRecords`。
4. 旧状态中的执行记录正确合并进完成记录。
5. 旧完成记录没有执行记录时迁移为空数组。
6. 重复迁移与重复 Learning MORE 同步不产生重复时间段。
7. 撤销完成后，时间轴条目和未配置时间条目同时消失，XP 补偿保持正确。
8. 当前真实数据库的复现条件从“34 条本周完成、0 条时间线记录”变为“34 条本周完成均可见，其中无实际时间者位于顶部区域”。

类型检查、完整测试集和生产构建均需通过。

## 非目标

- 不推断或补写历史实际执行时间。
- 不改变计划排期。
- 不改变奖励、XP 或结算的业务规则。
- 不在本次修复中增加完成记录的事后时间编辑功能。
