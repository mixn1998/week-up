# Week UP 产品与系统设计规格

- 初版日期：2026-07-19
- 最近修订：2026-07-20
- 状态：最终简化设计已确认，首个交互式 Web Demo 已完成，高数据量兜底规则已确认
- 项目位置：仓库根目录
- 用户时区：Asia/Shanghai

## 1. 产品定义

Week UP 是一个面向单个用户的、本地优先且支持跨设备同步的游戏化行动管理系统。它把月目标、周行动方向、具体计划、时间段日程、完成事实和结构化复盘连接起来，用属性经验、像素徽章升级和周期成长总结提供可见反馈。

产品首先解决的问题是提高计划实际完成率、减少拖延。所有反馈必须能追溯到真实行动，不建立与行动脱节的战斗、货币或虚拟经济系统。

核心闭环：

```text
月目标
→ 周行动方向
→ 具体计划与时间段
→ 完成或未完成
→ 属性经验结算
→ 像素徽章进度与升级
→ 周回顾 / 月回顾
```

Learning MORE 的每日课表直接同步为 Week UP 计划，课节完成状态直接同步为 Week UP 完成事实；正式完成整门课程后额外生成技能书收藏。体重管理小组件提供独立的事实记录与趋势展示。课表同步本身不自动决定属性奖励，技能书与体重记录也不改变属性经验和徽章等级。

## 2. 目标与非目标

### 2.1 产品目标

1. 让用户把宽泛的月度和周度方向转化为具体日程。
2. 让每一次完成行动都产生即时、清晰且可追溯的属性成长反馈。
3. 让用户在周末和月末准确看到完成内容、未完成内容、属性增长来源和徽章升级。
4. 在 Windows Web 与 Android 之间提供可离线、可恢复的单用户同步。
5. 与 Learning MORE 建立唯一外部联动，直接同步每日课表、课节完成状态，并收藏正式完成的课程技能书。
6. 通过体重趋势小组件展示长期变化，不提供医疗判断。

### 2.2 非目标

- 不提供多人账号、社交、公会、排行榜或公开分享社区。
- 不使用 AI 建议属性、奖励数值、目标、回顾内容或健康结论。
- 不把徽章等级宣称为现实能力测评结果；它表示行动积累等级。
- 不接入 Learning MORE 之外的外部项目。
- 不提供金币、商店、装扮、衣柜、怪物、Boss、战斗、装备、道具或技能效果。
- 不提供连续打卡、连胜倍率或失败扣分。
- 不提供饮食热量、运动消耗、体脂率、腰围或医疗建议。
- 不提供现实奖励券或现实商品兑换。

## 3. 用户、终端与同步边界

### 3.1 用户与终端

- 单个本地用户。
- Windows Web/PWA 是完整工作台。
- Android App 是轻量伴侣端。
- Windows 与 Android 都有持久化本地数据库，断网时仍可查看和修改数据。

### 3.2 跨端分工

Windows Web/PWA 负责：

- 月目标、周目标与完整计划管理；
- 周/月日历与时间段安排；
- 自定义属性与计划奖励配置；
- 周/月回顾与感想；
- 徽章和技能书收藏；
- 完整体重趋势视图；
- 同步、设备、冲突与恢复管理。

Android App 负责：

- 查看今日计划与本周概览；
- 完成打卡；
- 快速新增计划；
- 查看任务结算卡、徽章进度和技能书；
- 录入今日体重并查看紧凑趋势图。

### 3.3 私有同步服务

Windows 与 Android 通过仅服务该用户的私有同步服务交换变更。同步服务保存版本化变更日志和数据快照，负责设备配对、幂等校验和全局排序；它不是客户端操作的前置条件。

新设备通过已登录设备生成的一次性配对码加入。用户可以撤销丢失设备。所有传输必须使用加密连接。

## 4. 目标、计划与日程

### 4.1 目标层级

```text
月目标（长期方向）
└─ 周目标（本周行动方向）
   └─ 计划发生项（具体行动与时间段）
```

- 月目标可以关联多个周目标。
- 周目标可以使用宽泛描述，不要求在目标文本中写出数量。
- 具体计划可以关联零个或一个周目标。
- 目标进度由关联计划的完成事实计算，不从文本推断。

### 4.2 目标结算

- 周目标至少关联一项本周有效计划，且所有关联计划均完成时，结果为 `achieved`。
- 周目标存在未完成关联计划时为 `not_achieved`；没有关联计划时为 `no_action`。
- 月目标至少关联一个当月周目标，且所有关联周目标均为 `achieved` 时，结果为 `achieved`。
- 月目标存在未达成或无行动周目标时为 `not_achieved`；没有关联周目标时为 `no_action`。
- 同一周期有一个或多个目标达成时，系统只播放一次合并的像素庆祝演出。

### 4.3 计划与重复规则

计划支持：

- 标题与说明；
- 任务类型；
- 日期、开始时间和结束时间；
- 单次或重复规则；
- 关联周目标；
- 一个或多个自定义属性经验奖励。

重复计划通过计划模板生成独立发生项。结算、取消、改期和完成均针对发生项，避免修改模板时污染历史。

计划发生项状态为：

- `scheduled`：已经安排，尚未到结算边界；
- `completed`：用户主动完成；
- `missed`：到周期边界仍未完成；
- `cancelled`：用户主动取消，不进入完成率和目标结算。

## 5. 完成结算与即时反馈

### 5.1 二元结算

每项计划只有完成和未完成两种奖励结果：

- 完成：获得计划中配置的全部属性经验。
- 未完成：不获得经验，也不扣除既有经验。

属性与经验值完全由用户设置，系统和 AI 都不自动建议或修改。

### 5.2 奖励快照

计划完成时，系统在同一个本地事务中保存：

- 完成事实；
- 完成时间；
- 当时的计划标题；
- 属性奖励快照；
- 来源目标和计划发生项 ID。

之后修改计划，不追溯改变历史奖励。

误标完成通过补偿交易撤销对应经验，并恢复计划状态；系统不得删除原完成事实。

### 5.3 像素任务结算卡

本地事务成功后立即显示像素任务结算卡：

```text
COMPLETE!
打羽毛球
敏捷 +1　协调 +1
```

结算卡只展示本次真实变化。网络和同步失败不得阻止本地结算，也不得让已经显示成功的完成事实静默消失。

## 6. 自定义属性与像素徽章

### 6.1 属性定义

用户可以自由创建属性，并配置：

- 名称；
- 像素徽章；
- 显示颜色；
- 可选说明。

属性名称、图标、颜色和说明可以修改；历史行动继续引用同一个稳定属性 ID。

### 6.2 经验与等级曲线

所有属性徽章使用同一条温和递增曲线：

```text
从当前等级 L 升到 L+1 所需经验 = 5 × (L + 1)
```

默认从 Lv.1、0 经验开始：

| 升级 | 本级所需经验 | 累计经验 |
|---|---:|---:|
| Lv.1 → Lv.2 | 10 | 10 |
| Lv.2 → Lv.3 | 15 | 25 |
| Lv.3 → Lv.4 | 20 | 45 |
| Lv.4 → Lv.5 | 25 | 70 |
| Lv.5 → Lv.6 | 30 | 100 |

### 6.3 徽章反馈

- 每次增加经验都更新徽章经验条和剩余升级经验。
- 一次计划跨过多个等级时，系统一次性结算全部等级，并在动画中显示 `连续提升 N 级`。
- 升级记录永久保存，包含属性、升级前后等级、触发行动和时间。
- 经验补偿可能导致等级下降；系统显示修正记录，不播放惩罚动画。
- 徽章经验和等级只表示真实行动积累，不参与其他货币或兑换系统。

## 7. 周期结算与结构化回顾

### 7.1 周期边界

- 日状态结算：次日 `00:00` 将前一日未完成的有效计划标记为 `missed`。
- 周结算：每周一 `00:00` 结算刚结束的周一至周日。
- 月结算：下月第一天 `00:00` 结算上一个自然月。
- 所有边界使用用户时区 Asia/Shanghai。

设备或同步服务跨过边界时离线，下次启动必须补做缺失结算。每日、每周和每月结算使用唯一周期键，多个设备同时补结算也只能产生一个当前有效版本。

### 7.2 周回顾

周回顾由确定性规则生成，不调用 AI，包含：

- 周目标及结算结果；
- 已完成计划；
- 未完成计划；
- 各属性经验增长及具体行动来源；
- 本周徽章升级；
- 本周获得的技能书；
- 用户填写的感想。

### 7.3 月回顾

月回顾由确定性规则生成，不调用 AI，包含：

- 月目标及关联周目标结果；
- 月内完成与未完成行动汇总；
- 各属性月初、月末经验与净增长；
- 各属性月初、月末等级与升级记录；
- 经验增长的具体行动来源；
- 本月获得的技能书；
- 体重月初、月末、变化值和 7 日移动平均趋势；
- 用户填写的感想。

回顾冻结后不能原地改写事实部分。用户感想可以追加修订，并保留版本历史。

## 8. Learning MORE 课表、完成状态与技能书联动

### 8.1 每日课表同步

Learning MORE 是 Week UP 唯一允许直接创建计划的外部来源。Learning MORE 创建、移动、取消或恢复课表项时，Week UP 根据下列字段建立或更新对应计划发生项：

- `scheduleItemId`：外部幂等键；
- `courseId` 与 `lessonId`：课程和课节来源；
- 课程标题与课节标题；
- `startAt` 与 `endAt`；
- `timezoneAtCreation`；
- `source`、`locked` 与课表状态。

同一 `scheduleItemId` 在 Week UP 中只能对应一个计划发生项。Learning MORE 移动或取消尚未完成的课表项时，Week UP 更新同一发生项而不是重复创建。已形成完成事实的计划不被后续课表编辑追溯改写，只保留来源修订记录。

同步创建的计划显示 `Learning MORE` 来源标签，并可关联 Week UP 周目标。属性奖励仍由用户在 Week UP 中配置；未配置奖励的外部计划可以正常同步和完成，但不会产生属性经验。Learning MORE 不得自动填写、建议或修改属性奖励。

### 8.2 课节完成状态同步

Learning MORE 的课节状态 `completed` 是同步完成 Week UP 对应计划的唯一权威条件。同步适配器使用 `scheduleItemId + lessonId` 定位计划发生项，并写入带外部来源快照的完成事实：

- Learning MORE 完成时间；
- 课节与课程 ID；
- 课表项 ID；
- 同步事件或快照版本；
- Week UP 当时已经配置的属性奖励快照。

同一外部完成状态只能结算一次。若 Week UP 已经由用户手动完成对应计划，后续 Learning MORE 完成同步只补充外部来源凭证，不重复增加经验。若 Week UP 先撤销手动完成、但 Learning MORE 仍为 `completed`，下次同步会恢复由外部事实支持的完成状态。

首版同步通过本地私有连接读取 Learning MORE 的课表视图和课节状态，并维护增量游标；应用启动、恢复网络、Learning MORE 发生课表或完成变更时自动刷新。同步暂时不可用时保留 Week UP 本地计划与待处理游标，恢复后补齐，不要求用户二次创建或二次打卡。

### 8.3 课程完成与技能书接入合同

Learning MORE 只在正式课程完成后发布事件。事件至少包含：

- `eventId`；
- `courseId`；
- `courseVersionId`；
- 课程标题；
- 课程类别；
- 正式完成时间；
- 来源修订号。

草稿、失败任务、AI 文本、课节预览和未完成课程不能触发技能书。

同一 `courseId` 只生成一本永久技能书。重复完成事件只更新来源记录，不重复发书。

### 8.4 技能书收藏

- 技能书永久保留，不被任何行为消耗。
- 技能书显示课程标题、类别、完成时间、来源版本和像素封面。
- 技能书不提供属性经验、等级加成或技能效果。
- 周/月回顾把新技能书作为额外学习收获展示。

## 9. 体重管理小组件

### 9.1 范围

首版只记录：

- 每日体重；
- 目标体重；
- 7 日移动平均；
- 与上次有效记录的变化；
- 与当前 7 日移动平均的差值。

不记录体脂率、腰围、热量或运动消耗，不输出医学判断、减重速度评价或饮食建议。

### 9.2 录入规则

- Windows 与 Android 都支持手动录入。
- 单位固定为千克，保存精度为 0.1 kg。
- 每个本地自然日只有一个当前有效体重值。
- 当天重复录入视为修正，旧值进入不可变修订历史。
- 历史日期允许补录；补录与修改都记录创建时间、设备 ID 和修订来源。
- 目标体重由用户手动设置，可以修改并保留版本历史。

### 9.3 7 日移动平均

某一天的 7 日移动平均使用该日及之前 6 个自然日内的有效体重值计算：

```text
7 日移动平均 = 窗口内有效体重值之和 / 有效记录天数
```

- 缺失日期不插值，也不按零计算。
- 窗口内只有一个有效记录时不显示移动平均，只显示原始体重。
- 至少两个有效记录时显示移动平均，结果保留 0.1 kg。

### 9.4 展示

今日页显示紧凑组件：

- 最新体重；
- 与上次记录的变化；
- 7 日移动平均；
- 目标体重；
- 最近 7–14 天迷你趋势线。

展开视图显示完整历史折线、7 日移动平均线和目标体重线。原始体重与移动平均必须使用不同视觉样式，避免混淆。

## 10. 页面结构

### 10.1 Windows Web/PWA

主导航：

1. 今日：本周方向、今日时间线、完成入口、成长快照和体重小组件。
2. 目标与计划：月目标、周目标、计划编辑和属性奖励配置。
3. 日历：周/月时间段视图、改期、取消和重复计划。
4. 周/月回顾：周期事实报告和用户感想。
5. 成长收藏：属性徽章、经验来源、升级记录和技能书。
6. 体重趋势：历史记录、移动平均、目标线和修订历史。
7. 设置与同步：设备、配对、冲突、备份和恢复状态。

### 10.2 Android App

底部入口：

- 今日；
- 本周；
- 成长。

今日页提供计划打卡、快速新增和体重录入。成长页提供徽章与技能书的轻量查看。完整目标编辑、回顾编辑、属性管理和体重历史修订首版保留在 Windows Web。

### 10.3 视觉系统：糖果电玩

Week UP 采用“糖果电玩”像素可爱风。视觉必须有明确识别度，不能只在普通圆角界面上添加像素字体或少量图标。

核心色板：

| 角色 | 色值 | 用途 |
|---|---|---|
| Ink | `#302447` | 主文字、3 px 像素描边、硬阴影 |
| Cream | `#FFF8EC` | 页面主背景 |
| Candy Pink | `#FF4D9E` | 主要行动、完成与升级强调 |
| Electric Cyan | `#85F2FF` | 数据、趋势与信息强调 |
| Pixel Yellow | `#FFE05B` | 里程碑、提示与高亮 |
| Mint | `#79F2B5` | 成功状态 |
| Violet | `#7457FF` | 导航选中与属性进度 |
| Coral | `#FF6B6B` | 错误与危险操作 |

视觉语法：

- 使用 8 px 基础间距网格。
- 主卡片使用 3 px Ink 描边和 5 px 无模糊硬阴影，圆角控制在 6–8 px。
- 主按钮使用高饱和填色、3 px 描边和按下位移；不能依赖渐变制造层级。
- 正文、表格和长回顾使用高可读无衬线字体；像素展示字体只用于品牌、短标题、等级、数字和英文状态标签。
- 数据区域以 Cream 或白色为底，高饱和色只承担重点、状态和互动，不大面积铺满正文背景。
- 像素质感必须同时体现在徽章精灵、图表节点、勾选框、边框、硬阴影、结算闪光和页面转场中。

关键组件：

- 计划行：时间、标题和完成按钮保持第一视觉层级，装饰不能压过日程信息。
- 任务结算卡：使用 Candy Pink、Mint 和 Pixel Yellow 强化本次属性增长。
- 属性徽章：每个等级至少有轮廓、色彩或细节变化；不能只替换等级数字。
- 体重图表：原始值使用 Ink 节点和细线，7 日移动平均使用 Electric Cyan 粗线，目标体重使用 Pixel Yellow 虚线。
- 技能书：使用统一像素书脊结构，通过类别色、封面符号和标题区分。

动效约束：

- 普通完成反馈控制在 450 ms 内，不阻塞连续打卡。
- 徽章升级动画控制在 800–1200 ms，可点击跳过。
- 周/月合并庆祝演出控制在 2.5 秒内，可重复查看但不重复结算。
- 不使用每秒超过 3 次的闪烁。
- 开启减少动画设置后，所有动画替换为静态结果卡和一次颜色变化。

可访问性：

- 正文默认字号不小于 14 px。
- 所有交互热区不小于 44 × 44 px。
- 颜色不能作为状态的唯一表达，同时提供文字、图形或图标。
- 键盘焦点使用清晰的 Violet 与 Ink 双层轮廓。
- 关键文本和背景满足 WCAG AA 对比度要求。
- Android 紧凑布局保留相同色板和描边语法，但减少装饰密度，保证触控和信息扫描效率。

### 10.4 高数据量与信息密度兜底

Week UP 使用“渐进披露 + 用户控制密度”的确定性规则处理大量属性、日程和历史数据。系统不得使用 AI 决定隐藏哪些内容，也不得在没有明确入口的情况下省略真实记录。

通用规则：

- 每个折叠、截断或聚合位置必须显示准确数量，例如“已完成 12 项”或“还有 7 项”。
- 默认使用舒适密度；用户可手动切换紧凑密度，系统不得在使用过程中突然自动切换。
- 搜索、筛选、分组和排序状态在页面切换后保留于本地设备。
- 关键行动与异常状态不能只因为数据量增加而被折叠；今日正在进行、逾期和同步冲突始终可见。
- 长列表使用虚拟滚动或分页加载；任何页面不得一次挂载全部历史记录。

属性密集场景：

- 今日页只展示最多 4 个用户置顶属性；不足 4 个时按最近获得经验时间倒序补齐，同时间按属性 ID 排序。
- 今日页始终显示“全部 N 项”入口，未展示的属性不得被解释为不存在。
- 成长收藏页支持名称搜索、类别筛选、等级排序、最近增长排序和用户置顶。
- 属性数量超过 30 时，徽章网格必须虚拟化；初始渲染不超过 24 枚徽章。
- 计划奖励标签最多直接展示 3 个，其余折叠为“+N”；展开后显示完整属性与经验值。
- 已停用属性默认进入归档筛选，但历史经验来源继续显示原名称快照。

日程密集场景：

- 今日列表按“正在进行、接下来、稍后、已完成”分组；正在进行与接下来始终展开。
- 当日有效计划超过 8 项时，已完成分组默认折叠，并提供明确计数；计划超过 20 项时列表虚拟化。
- 周日历同一时间段最多并排展开 3 项，更多计划合并为“+N”堆叠入口。
- 单日超过 6 个日历块时，周视图先保留正在进行、逾期和同步冲突项，再按开始时间从早到晚补足 6 项，并显示“查看当天全部 N 项”入口；完整内容在当日议程抽屉中展示。
- Android 不压缩七列周日历，默认使用按日期分组的议程列表；桌面端保留周日历与议程列表切换。
- Learning MORE 同步计划使用来源筛选器，不获得高于手动计划的默认视觉优先级；进行中、逾期或冲突状态除外。

历史与聚合数据：

- 周/月回顾每个事实区按事实发生时间倒序展示前 5 条，之后显示“展开全部 N 条”。
- 体重与经验趋势提供 7 日、30 日、90 日和自定义时间范围；长周期图表按可见像素宽度等距分桶，每桶保留首值、末值、最小值和最大值，但统计结果始终使用原始数据。
- 历史流水每页最多 50 条，并支持日期、来源、状态和属性筛选。
- 属性总经验、徽章等级、周/月汇总和移动平均使用增量投影；页面读取投影和分页事实，不在前台反复扫描完整账本。
- 同步使用增量游标拉取变更，不因新增设备而默认下载并渲染全部历史页面。

压力测试模式只用于开发与视觉回归，不进入用户正式数据。它一次性生成：

- 30 个属性，其中 4 个置顶；
- 一周 50 项计划，包含重叠时间、已完成、未完成和 Learning MORE 来源；
- 365 天体重与经验历史；
- 足以触发折叠、筛选、分页、虚拟化和图表下采样的回顾事实。

关闭压力测试模式后必须恢复进入前的本地 Demo 状态，不得把压力数据写入正式数据存储或同步队列。

## 11. 系统模块与数据流

### 11.1 模块边界

| 模块 | 职责 |
|---|---|
| 目标与计划 | 目标层级、计划模板、计划发生项和时间段 |
| 行动账本 | 完成、未完成、取消和奖励快照事实 |
| 属性结算 | 属性经验交易、等级投影和升级记录 |
| 复盘引擎 | 周/月周期结算与结构化报告 |
| 成长收藏 | 属性、徽章、经验来源和技能书 |
| 体重记录 | 每日有效值、修订历史、目标体重和移动平均 |
| 同步与接入 | 设备同步、冲突、Learning MORE 课表/完成状态/课程事件和恢复 |

### 11.2 完成计划的数据流

```text
用户点击完成
→ 本地事务写入完成事实
→ 冻结属性奖励快照
→ 生成属性经验交易
→ 重建徽章等级与升级记录
→ 立即显示像素任务结算卡
→ 变更进入同步待发送队列
→ 其他设备拉取事实并重建相同投影
```

所有经验交易使用完成事实 ID 与属性 ID 的组合作为幂等键。

### 11.3 Learning MORE 同步的数据流

```text
Learning MORE 创建或更新每日课表
→ Week UP 以 scheduleItemId 幂等导入或更新计划发生项
→ 用户在 Week UP 配置可选属性奖励
→ Learning MORE 将课节状态更新为 completed
→ Week UP 以 scheduleItemId + lessonId 定位对应计划
→ 写入或补充唯一完成事实
→ 按 Week UP 已冻结的奖励快照结算经验
→ 今日页、徽章与回顾立即刷新
```

### 11.4 体重录入的数据流

```text
用户录入体重
→ 本地校验数值和自然日
→ 写入新的体重修订记录
→ 更新该日当前有效值
→ 重算受影响日期的 7 日移动平均
→ 立即刷新趋势组件
→ 进入同步待发送队列
```

## 12. 同步、冲突与恢复

每个变更携带唯一 ID、设备 ID、逻辑发生时间、创建时间和基础版本。

- 完成事实、经验交易、技能书导入和体重修订采用追加式记录。
- 目标、计划文本、日程字段和目标体重采用版本化可变记录。
- 不同字段的并发修改自动合并。
- 同一字段的并发修改不静默覆盖，保留冲突版本供用户选择。
- 同一天体重在两台设备被分别修改时，两个修订都保留；用户选择当前有效值。
- 同步服务不可用时，客户端保留待发送队列并指数退避重试。
- 页面显示同步状态，但失败不撤销本地成功操作。

周期结算原则：

- 在周期截止前已经创建、但截止后才同步的离线完成事实，必须通过补充结算纳入对应周期并留下修订记录。
- 周期截止后才创建的历史编辑不自动改变冻结结算；用户必须显式重新打开结算。

## 13. 错误处理与数据完整性

- 同一完成事实的同一属性只能结算一次经验。
- 同一周期只能存在一个当前有效结算版本。
- 同一课程只能生成一本技能书。
- 同一天只能有一个当前有效体重值，但所有修订必须保留。
- 经验总量、徽章等级、回顾和移动平均必须能从事实记录重建。
- 本地事务失败时不得显示成功结算动画。
- 服务端拒绝同步时，本地记录进入可恢复错误状态，不得静默丢弃。
- 体重数据导出、备份和删除使用与其他个人数据相同的权限和恢复规则。

## 15. MVP 验收标准

1. Windows 可创建、编辑和安排月目标、周目标及计划。
2. Android 可离线查看今日计划、完成打卡和快速新增。
3. 属性和经验完全由用户配置；完成后即时结算且不重复。
4. 徽章按统一曲线升级，并能追溯每一点经验的行动来源。
5. 日、周、月周期结算可跨停机补做且结果唯一。
6. 周/月回顾准确列出目标、完成内容、未完成内容、属性来源、徽章升级和用户感想。
7. Learning MORE 每日课表可直接创建或更新 Week UP 计划，课节完成状态可直接完成对应计划；重复同步不得重复创建或重复结算。
8. Learning MORE 正式完成课程后，只生成一本永久技能书。
9. Windows 与 Android 可手动录入体重并同步。
10. 体重小组件正确显示每日值、7 日移动平均和目标体重线。
11. Windows 与 Android 同步后得到相同事实和投影；冲突不被静默覆盖。
12. 所有汇总值都能从事实记录重建。
13. 30 个属性、50 项周日程和 365 天历史同时存在时，今日关键行动仍可直接操作，完整数据均有可达入口，页面不一次渲染全部历史。

产品成功标准：连续使用四周后，用户能够清楚看到计划完成率、未完成行动、属性成长来源、徽章变化、课程收藏和体重趋势，并感到每次行动都获得了即时且可信的反馈。
